# Documentation Mode Policy

## Purpose

Define maximum useful detail for Harness V3 documentation.

## Rule

Documentation should be dense enough to support handoff and review, but not padded with unbounded repetition.

## Required Section Depth

Major sections should answer:

- what is this
- why it exists
- how it works
- where it applies
- what can go wrong
- how it is validated
- concrete example or evidence when useful

## Architecture Requirement

Use architecture-as-text for complex systems. Use Mermaid when flow, lifecycle, state, dependency, or ownership matters.

## Anti-Patterns

- shallow bullet-only artifacts
- marketing-style claims without source references
- repeating the same table without adding meaning
- hiding uncertainty
- documenting desired runtime behavior as if it is already enforced
