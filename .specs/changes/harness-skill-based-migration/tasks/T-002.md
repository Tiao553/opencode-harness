# T-002: Resolve Effective OpenCode Configuration Precedence

## Objective

Produce a sanitized, evidence-backed report of the OpenCode executable, config locations, active environment overrides, and current MCP CLI state without changing runtime configuration.

## Inputs

| Input | Required use |
|---|---|
| T-001 baseline | Establish the current repository and dirty-worktree context |
| `opencode debug paths` | Verify discovered global config, data, state, and cache roots |
| `opencode --version` and executable resolution | Identify the active CLI binary and version |
| `opencode mcp list` | Record official MCP CLI state |
| Sanitized environment | Record HOME, XDG_CONFIG_HOME, OPENCODE_CONFIG, and OPENCODE_CONFIG_DIR paths or unset state |
| `opencode.json` and `opencode.jsonc` | Identify project/global config candidates without modifying them |

## Allowed Paths

- `.specs/changes/harness-skill-based-migration/state.md`
- `.specs/changes/harness-skill-based-migration/allocation.yaml`
- `.specs/changes/harness-skill-based-migration/tasks/T-002.md`
- `.specs/changes/harness-skill-based-migration/evidence/t-002-config-provenance.md`
- `.specs/memory/harness-skill-based-migration/bootstrap-decisions.md`

## Forbidden Paths

- `AGENTS.md`, `opencode.json`, `opencode.jsonc`
- `agents/`, `commands/`, `skills/`, `plugins/`, `tools/`, `test/`
- `.specs/memory/active-state.md`
- Any `.env` or `.env.*` file

## Required Rules and Tools

- Required rules: Roadmap V2 W0 T-002 contract, source authority hierarchy, no-secret evidence rule.
- Required skills: `task-spec`, `customize-opencode`.
- Allowed tools: RTK, Git, OpenCode CLI, Read, Glob, Grep, Bash, Apply Patch, TODOWRITE.
- Allowed MCPs: none.
- Execution profile: primary parent session; no delegation.

## Deliverables and Acceptance Criteria

- [x] The report identifies the executable path and version used by the CLI.
- [x] The report records HOME, XDG_CONFIG_HOME, OPENCODE_CONFIG, and OPENCODE_CONFIG_DIR as sanitized paths or unset.
- [x] The report names config candidates and explains precedence from current evidence.
- [x] The report preserves official `opencode mcp list` output and explains the UI/CLI discrepancy as resolved or unresolved.
- [x] The report contains no secret, credential, or token value.
- [x] No file outside Allowed Paths changes.


## Evidence and Rollback

- Evidence: the sanitized provenance report and captured CLI results.
- Rollback: remove the T-002 Task-Spec and evidence, then restore T-001 state/allocation content.

## Stop Conditions

- The report would include a secret value.
- A precedence claim lacks runtime or disk evidence.
- Resolving provenance requires changing active configuration.
- A required diagnostic command is unavailable.
